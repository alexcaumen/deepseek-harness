# Server Manager 模型生命周期适配器

[English](README.md) | 中文

`@deepseek-ai/dsh-model-lifecycle-server-manager` 是受治理模型生命周期运行时与已准入 Giana Server Manager 资源 API 之间的传输中立适配器。它同时实现 `ResourceLeaseProvider` 和 `ModelLifecycleDriver`，而注入的传输仍负责端点发现、身份验证、凭据、重试策略和线路访问。

该适配器不选择提供方、模型、路由、目标、会话或回退。其选项要求 owner 签发的目标身份与时效性摘要、签发方与持有方身份、准入摘要、有界租约与操作时限，以及已验证的最大时钟偏差。本包不嵌入主机、API 路径、模型路径、进程命令或 secret。

## 契约

资源获取会请求完全覆盖调用方已准入的目标。适配器在暴露授权前验证规范回执摘要、schema、租约身份、签发方、持有方、准入、覆盖范围、到期时间、续租计划、目标身份和时效性。它会从可用生命周期中扣除已配置的时钟偏差边界和本地操作预算。生命周期缺失或耗尽时封闭失败。

每个生命周期事务只会在检查调用方取消状态和期限后，才在第一个阶段惰性开始。每个阶段请求都携带 owner 租约 id、数字 fence 与 generation、不可变事务类型、事务摘要、作用域摘要、路由、修订、目标和幂等 key。摘要绑定的阶段回执必须回显并绑定路由 id、目标类别和精确修订摘要，同时绑定事务、作用域与 fencing 值，并通过有效的阶段状态从上一份回执推进。失败的预状态回执以及重复或不匹配的目标都会封闭失败。预检可以返回显式 unavailable 结果；仅发生容量不足的事务会先干净取消，然后才以 `SETTLED` 释放租约。尝试过变更阶段后，不确定的清理会以 `UNCERTAIN` 释放，交由 owner 隔离。

适配器把调用方取消传给注入的传输，并且不执行隐藏重试。传输只能用同一个幂等 key 重试，并且必须拒绝 unknown-commit 结果。健康决策把 `UNHEALTHY` 保留为有类型的 false 结果，使生命周期控制器能运行其有界恢复路径。私有租约 id、数字 fence、generation 和线路载荷绝不进入公共授权或已净化的适配器错误。

## 模型体验

### 受治理资源执行

#### 模型看到的内容

模型不会从 `@deepseek-ai/dsh-model-lifecycle-server-manager` 收到任何直接适配器上下文。外围生命周期运行时可以延迟推理，直到已准入路由就绪，或返回有类型的已净化失败。

#### Token 影响

没有直接 token 影响。失败的准入发生在推理前；成功切换只会改变由其他权威选择的底层路由。

#### KV Cache 影响

相互独立。该适配器不重写对话历史或模型输入。

## 已知限制与暂缓事项

- **仅 source gateway**：本包不包含已准入传输、端点、凭据、目标身份、路由注册或 live Server Manager 部署。
- **Owner 协调仍在外部**：`UNCERTAIN`、过期、撤销或 unknown-commit 操作需要部署 owner 隔离并协调物理状态。
- **时钟纪律由部署提供而非本包测量**：部署必须提供当前有效、已验证的最大偏差，并在该证据过期时拒绝操作。
- **执行 fencing 由 owner 强制**：客户端验证不能替代每个物理变更端点的原子 fence 强制。
- **不执行路由晋升**：安装该适配器不会让 held 模型变为可用，不会更改默认值，也不证明 R5300、PRDG、RAM/CPU、Putri、Qwen 或 GLM 已 live。
