# 模型生命周期

[English](README.md) | 中文

`@deepseek-ai/dsh-model-lifecycle` 是受治理本地模型的提供方无关执行边界。它管理一个串行化的大模型槽位、动态目标准入、推理租约和回滚。LLM 服务仍是唯一的提供方／模型选择权威。主机专用的 GPU、RAM、CPU、进程、启动和健康检查机制仍位于已注册驱动之后。

该服务有意与语音路由分离。它既不调用也不配置 STT/TTS 计算端点，并且不携带模型载荷路径或凭据。

## 服务契约

`ctx.modelLifecycle.installAuthority()` 安装唯一的提供方分类器、路由／作用域解析器和已净化审计接收器。`ctx.modelLifecycle.installResources()` 则单独安装唯一的、由部署方拥有的共享资源租约提供者，因此 Server Manager 适配器不能仅凭提供主机机制就取得路由、作用域或审计权威。随后，`register()` 将主机机制附加到一条不可变路由。外部提供方在进入本地 FIFO 前完成分类；受治理本地请求在异步解析前进入 FIFO，因此较快的后续解析器不能越过较早请求。解析和审计持久化会收到运行时拥有的取消信号，并且必须在期限到期时停止远程工作。权威必须解析出与已注册驱动一致的提供方／模型、路由身份、准入摘要和修订摘要。受治理路由若缺少权威、作用域、准入或驱动数据，或这些数据不匹配，则会在资源操作前封闭失败；普通外部提供方仍不受管理。

`acquireRoute()` 将受管理推理串行化。其持久化 `preference` 设置接受 `automatic`、`r5300` 或 `prdg`。Automatic 路由先探测 R5300，再探测 PRDG，并且只有路由清单明确允许 offload 时才探测 RAM/CPU。手动 R5300 或 PRDG 意图只探测该目标，并返回类型化失败，而不会静默派发到其他位置。每次受管理获取都携带不可变的工作、主体、租户和会话作用域，并在资源操作前重新计算其规范摘要。

该服务在完整的提供方／模型请求形成后包装 `llm/stream`。对于真实切换，它会先执行容量预检，再捕获原状态，随后执行有界排空、停止和停止后验证、精确修订启动、健康检查及能力探测，然后才开始适配器迭代。`stageTimeoutMs` 为每次主机驱动调用提供明确期限和必需的取消信号；驱动必须遵守该信号。每个阶段回执都必须匹配路由、目标、修订、作用域和事务。回滚阶段保留当前 `MODEL_ROUTE` 事务类型、作用域和摘要，不创建第二个回滚事务。返回的租约贯穿完整异步流，并在 `finally` 中释放，因此其他受管理请求无法在推理途中卸载活动模型。已验证的部分失败会恢复先前健康路由。若变更操作超时、清理未验证、回滚失败或审计权威失败，本地槽位会被标记为不可信，并在主机协调或有序重启前拒绝后续受治理本地工作；控制器不会让推测性回滚与物理状态未知的操作竞态运行。明确拒绝的 `READY` 审计会执行已验证回滚；超时的 `READY` 写入可能延迟结算，因此会保留物理就绪的路由并将其置于 `TAINTED` 隔离状态，延迟结算会触发一次绑定同一事务且有期限的 `TAINTED/AUDIT_FAILED` 补偿尝试。

`minimumDwellMs` 和 `idleUnloadMs` 实施防抖策略。最后一个推理租约释放后，服务只启动一个自有计时器，等待两个限制均满足，然后在同一串行槽位内停止并验证空闲路由。将 `idleUnloadMs` 设为零可禁用定时卸载。每个就绪、释放、回滚、拒绝和空闲卸载结果都会作为仅含摘要的已净化审计记录发送给权威。

## 扩展点

推理准入受 `maxPendingRequests`（默认 32，不包含当前租约）和 `queueTimeoutMs`（默认 120,000 毫秒）限制。队列已满时返回 `QUEUE_FULL`，等待超时时返回 `QUEUE_TIMEOUT`。取消或到期会立即移除等待项，不会停止活动推理、更改驻留状态或调用权威组件及驱动。待处理容量为零时仍允许立即获取，但拒绝排队推理。内部有序关闭和空闲卸载保留 FIFO 位置，不受推理准入限制，避免过载跳过资源清理。

专用资源安装必须提供由部署管理的 `ResourceLeaseProvider`，受治理主机操作才可运行。应用请求覆盖当前已注册可用目标，并消费外部签发的租约、签发方、持有方、fencing、回执和到期信息。它既不签发租约，也不把逻辑目标映射到物理 GPU。部署在返回授权前验证规范身份、物理资源覆盖、时效性与准入；每个驱动必须在执行端点原子执行 fencing。客户端检查覆盖范围，在每个阶段附带授权和明确的事务类型，并要求阶段回执绑定 fencing 摘要。

`ResourceLeaseSession` 按提供方的计划续租，并使用独立到期监控。资源所有权贯穿推理和空闲驻留，包括回滚与关闭。撤销、到期或续租失败会取消阶段及推理信号，将运行时标记为不可信，并阻止过期清理。仅在本地工作静止后释放才报告 `SETTLED`，不确定失败后报告 `UNCERTAIN`。两者都不能证明远程 GPU 为空，也不能跳过部署调和直接重新分配。适配器和驱动必须遵守取消信号；即使客户端消失，部署仍须隔离不确定工作并执行 fencing。

流包装层保存请求作用域的租约信号，通过 `llm/dispatch-signal` 提供取消，不修改 agent loop 的冻结请求。提供方获取、续租和释放均有期限，并且获取操作会收到调用方的取消信号。关闭会取消续租，并等待一次有界尽力释放；如果关闭在续租开始后发生，即使请求了 `SETTLED`，当前授权也会以 `UNCERTAIN` 释放。释放失败会被隔离，但不证明远端清理完成。权威与资源安装会保持占用，直到每个底层提供方调用实际结算，包括超过调用方期限的调用。迟到的获取与续租结果都会使用实际结算的回执，尝试一次有界的 `UNCERTAIN` 释放。不响应取消的调用可能超过期限，仍需 owner 调和。

`capturePrestate()` 必须在预状态回执中绑定目标的最新占用状态：`EMPTY`、包含路由与修订的 `RESIDENT` 或 `UNKNOWN`。没有活动路由的运行时要求目标为空，不会接管另一进程遗留的驻留模型。复用、空闲卸载及关闭都要求驻留路由和修订与活动路由匹配。跨目标切换会检查两台主机。不匹配会返回 `RESIDENCY_UNVERIFIED`，将运行时标记为不可信，并阻止清理阶段停止未知占用者。关闭前读取预状态失败也会阻止停止。这些检查只能发现本地状态过时，既不是分布式锁，也不能代替主机执行的 fencing。

已准入路由可通过不可变的 `stageTimeoutsMs` 为指定阶段覆盖期限。数值必须是正整数毫秒且在计时器安全范围内，并与权威解析的路由一致。未指定的阶段与权威操作仍使用 `stageTimeoutMs`。因此加载缓慢的路由可以延长 `start` 期限，而不延长健康检查或队列解析期限；修改预算需要更新路由准入。

部署插件安装规范权威，并注册路由驱动以检查当前资源及执行精确且绑定修订的模型机制。驱动不能对路由分类、选择回退目标或自行构造作用域。GianaOS/GDM 或其他准入 owner 继续负责身份、策略、时效性、凭据、路由分类、作用域和持久审计。

## 模型体验

### 受治理模型选择

#### 模型看到什么

模型不会看到直接上下文，因为 `modelLifecycle` 只在推理期间协调主机资源。

#### Token 影响

无直接 token 影响。

#### KV Cache 影响

彼此独立。路由获取接收已经形成的提供方／模型请求，并可能在该次推理前切换后端资源；本包不会重写保留的对话输入。

## 已知限制与延期工作

- **不含主机机制**：任何受治理本地路由运行前，部署必须安装其规范权威并注册精确路由驱动。
- **无权威时分类范围有意受限**：未安装权威时，只能识别已注册选择为受治理对象。部署必须在暴露任何本地适配器之前安装权威。
- **没有已部署的资源签发方**：本包包含租约消费者，而非全局控制器、传输、凭据映射、物理 GPU 分配器或持久 fencing 存储。测试使用模拟签发方。多客户端生产安全需要部署的真实提供方与执行端点 fencing。预状态检查本身不能消除检查与变更间的竞态；仅重启不授权接管或停止驻留模型。
- **保守的驻留所有权**：应用串行处理本地模型工作，并共同租用其已注册候选目标，直至验证卸载。驻留期间加入的新目标需要在释放后获得覆盖它的新租约。跨客户端驻留转移或接管需要 owner 支持的显式调和机制，不能依靠本地缓存路由。
- **不会提升路由**：仅加载本包不会注册模型、提升 held 路由或更改默认值。
