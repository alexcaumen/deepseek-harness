# Agent Note: Giana Code Putri 交互控件

Status: implemented

[English](2026-09-02-giana-code-putri-interaction-controls.md) | 中文

## Problem

Giana Code Putri 桌面候选版本继承了功能完整的 Web 对话机制，但其中若干能力通过不完整或容易误导的产品界面呈现。模型可见上下文仍使用上游 harness 名称，回复标注占据冗长文本行而没有与所选来源保持关联，推理内容过于突出地展开，提问接管界面缺少听写，编辑器没有清楚展示 Queue 与 Steer 的选择，听写波形移动过快，并且不可用的 R5300 强制路由仍可能保持选中。独立的 GianaOS Putri ACP 启动器还使用了不一致的 SSH 主机身份，因此子进程启动失败可能只显示为笼统的代理失败，而不是具有因果阶段且已脱敏的诊断。

如果通过重命名内部包、复制语音或插话服务、或更改持久会话语义来修复这些缺口，就会扩大迁移风险，并可能使现有会话、工具或来源信息与候选版本断开。产品层需要呈现统一的 Giana Code Putri 身份，同时保留现有运行时权威和兼容标识符。

## Decision

### Product identity

组装后的产品和模型可见产品上下文将应用标识为 Giana Code Putri。内部 `@deepseek-ai/dsh-*` 包名、`DSH_*` 兼容变量、harness 协议标识符、仓库历史、许可证和上游来源保持不变。因此，用户与模型可见的产品文案和构建、加载、诊断与归属所需的技术标识符明确分离。

### Response annotations

回复选区在选中文本和回复身份之外，还记录可选的起始与结束偏移。完整且安全的偏移会渲染编号来源高亮和标记，不完整或旧版载荷继续使用纯文本行为。编辑器把标注渲染为紧凑的编号控件，支持悬停和聚焦预览以及来源导航；已发送的用户消息使用相同标注的紧凑编号气泡。结构化载荷保持向后兼容，并且不引入第二个标注存储。

### Reasoning presentation

推理仍可通过对话记录中现有的折叠 disclosure 查看，但折叠摘要不再显示模型私有推理流中的移动文本行。该行只报告运行中或已完成状态，不显示容易误导的独立计时器，并且只在用户操作后展开完整推理。推理块与最终回答保持分离，因此流式处理和结算仍只呈现一次最终回答。

### Composer and question controls

当主回合运行时，显式 Queue 或 Steer 选择器驱动现有规范提交模式。它不会取消当前回合、替换严格的逐行插话操作、更改主机线协议，或改变 [使用空草稿 Cmd/Ctrl+Enter 插入整个 Web 队列](2026-08-06-web-queue-steer-all-gesture.zh.md) 所描述的空草稿全队列手势。底层交付和竞态语义仍由 [将排队的 Web 消息插入活动回合](2026-07-30-web-queue-steer-action.zh.md) 管理。

提问编辑器提供麦克风开始、停止、转录、重试、取消和卸载状态。它把转录附加到自定义答案，并通过显式客户端包依赖复用对话包的规范印尼语转录解析器和听写 reducer。它不会创建语音端点、路由器、凭据路径或录音存储。该呈现仍是 [提问 Web 呈现](2026-07-29-ask-question-web-presentation.zh.md) 的扩展。

主编辑器波形使用固定的 72 条历史记录，并大约每 97 毫秒推进一个样本，使完整穿越时间约为七秒。动画速度按时间计算，不依赖渲染频率或模型吞吐量。

### Route and launcher guards

只有返回的路由状态为 ready 时，强制 R5300 语音路由才会持久化。不可用或失败的路由会恢复 Automatic，在状态刷新前阻止立即再次选择，并解释失败而不声称 R5300 正在活动。Automatic 路由继续报告现有计算权威选择的就绪路由。

GianaOS Putri ACP 启动器对探测和启动路径使用一个固定的 SSH 主机身份和严格的已知主机验证。子进程失败会报告因果阶段和已净化的 stderr，同时隐藏令牌和私有载荷。启动器保留现有 ACP、会话、工具和提供者权威；它不会添加包装服务或回退路由器。

## Verification

聚焦的组件和义务测试覆盖产品认知、偏移和旧版标注载荷、来源导航、折叠推理与最终回答分离、Queue 和 Steer 选择、七秒波形、提问听写生命周期、R5300 回滚以及 ACP 启动诊断。客户端包验证证明提问包声明了其对话依赖，而不是直接访问另一个包的源码树。隔离 staging worktree 的仓库类型检查和生产构建通过。

此源代码变更不会重启或替换现有应用。打包候选版本的人工体验 QA、针对只读一致副本的会话兼容性、受控提升、回滚证明和生产冒烟测试仍然是同一个不可变候选版本的发布门槛。

已构建浏览器的回放预期包含折叠的 Thinking 状态、问题听写和忙碌消息选择器。无选项答案使用拉伸网格，使 textarea 在存在听写包装层时仍填满预留框。fresh-round-trip 场景执行本机 shell：Windows 将录制的 Bash fixture 的临时副本适配为 PowerShell，保留命令，并使用独立的 Windows 可访问性快照。它不安装 Bash 别名、不隐藏工具错误，也不更改共享录制。该 fixture 仍只在 POSIX 上录制。

## Supersession and related decisions

本决策完全取代历史 [Web 推理尾部滚动](../../archived/feature/2026-08-02-web-thinking-tail-scroll.md) 中记录的最新行移动预览与横向跟尾机制。旧说明的动机仍然有效：折叠行必须真实显示推理是否活动，而不强迫用户打开完整推理主体。替代方案明确放弃文本移动所表达的吞吐信号，改用运行中或已完成状态。

它部分取代 [推理分片的逐帧累计发布与浏览器压力验证](../testing/2026-08-03-opt-in-reasoning-chunk-browser-stress.zh.md)：逐帧快照发布和显式压力测试车道仍然有效，而 Think 摘要跟尾调度已不存在。队列与插话生命周期说明以及提问呈现说明继续管理各自机制。[提示词变量与工具引导所有权](../architecture/2026-07-05-prompt-variables-and-tool-guidance-ownership.zh.md) 继续管理 `harness:identity` 提示词段；本决策修改通过该 owner 提供的产品值。此前没有现行 Agent Note 管理回复选择标注、七秒波形、语音路由持久化或 ACP 启动器身份规则。

## Alternatives considered

**重命名内部包和兼容标识符。** 拒绝，因为这些名称是构建、配置、会话和来源输入，而不是普通产品文案。替换它们会扩大迁移与回滚范围，却不会改善用户可见身份。

**把标注作为格式化文本存入草稿。** 拒绝，因为逐行标签会失去精确来源关联，无法提供可靠导航或悬停预览，并迫使每个模型从文本中重建结构。可选偏移既保留结构，也保留旧版载荷兼容性。

**永久隐藏推理或默认展开推理。** 拒绝，因为永久移除会阻止用户检查，而默认展开会压过回答界面。默认折叠且可由用户展开的推理同时保留访问能力和焦点。

**让折叠推理跑马灯独立于流式输出。** 拒绝，因为它会在提供者停顿时继续移动，使暂停的模型看起来仍在活动。与合成运动相比，状态是更真实的折叠信号。

**在折叠摘要中保留最新推理行或固定后缀。** 拒绝，因为它会在主要回答界面暴露私有推理片段，可能切断单词或字形，并使吞吐可读性取决于内容长度。完整主体只在展开后可见。

**自动滚动展开的推理主体。** 拒绝，因为展开行是阅读界面；强制跟随会妨碍用户回滚查看较早的推理。

**为提问答案添加第二个听写服务。** 拒绝，因为主编辑器已经管理转录路由和生命周期语义。第二个服务会复制凭据、取消、路由选择和失败行为。

**通过新的主机操作实现 Queue 和 Steer。** 拒绝，因为现有输入模式和严格逐行插话操作已经管理所需语义。选择器只是这些机制的呈现控件，而不是新的交付协议。

**保留不可用的强制 R5300 选择。** 拒绝，因为持久化意图会被显示成活动路由，即使不存在就绪路由。恢复 Automatic 可使可见状态真实且可恢复。

**使用第一个能够解析的 SSH 别名。** 拒绝，因为身份漂移会使已知主机验证和失败归因变得不确定。一个固定别名使探测和启动证据可比较。

## Consequences

Giana Code Putri 提供统一的交互层，同时不更改现有会话身份、持久历史、模型或提供者路由、工具权威或内部包来源。用户获得紧凑的来源关联标注、可选推理可见性、问题听写、明确的忙碌回合交付选择、更平稳的波形和真实的计算选择。

折叠推理行不再通过移动文本预览表达 token 节奏。在用户展开之前，它只表达运行中或已完成状态；这以较少的被动吞吐细节换取更安静的回答界面，以及推理与最终回答之间更清晰的分离。

标注载荷具有可选来源偏移，因此客户端必须继续接受纯文本旧版载荷。提问包现在明确依赖一个对话客户端包。产品认知维护必须区分普通界面文案和技术来源，而不能全局替换上游术语。

源代码和自动门槛可以建立不可变发布候选版本，但不能建立 production green。激活仍要求先停止现有应用，让同一个打包候选版本通过人工体验 QA 与会话兼容性检查，证明回滚，并让已接受的制品通过有界生产冒烟测试。
