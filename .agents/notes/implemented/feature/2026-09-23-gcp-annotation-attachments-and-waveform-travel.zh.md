# Agent Note: GCP 批注附件与波形移动

Status: implemented

[English](2026-09-23-gcp-annotation-attachments-and-waveform-travel.md) | 中文

## Problem

产品负责人在实际使用后否决了 Giana Cowork Preview RC47 的输入框批注和听写波形。选中回复文本会在草稿中插入可编辑的 `@Annotation N` 结构化引用，同时在输入框内另外渲染一排编号气泡，因此同一条批注出现两次，用户正文与生成的标签共用一个缓冲区。波形每 97 毫秒一步把所有竖条整体移动一格，每根竖条都跳到相邻竖条的高度；每个采样只来自一次短暂的分析器读取，相邻竖条差异很大。被采纳的参照是 Codex 输入框：一个紧凑的“1 annotation”标签打开卡片，卡片列出每段选中文本及其编辑和删除控件，编号标记留在来源段落旁边。

## Decision

### 批注是输入框附件

会话输入外壳在草稿文本和图片 id 之外单独维护一个按 1..N 编号的有序批注列表，并通过 `InputState.annotations` 发布。添加选中文本从不修改草稿。删除一条后其余批注重新编号。每条批注可带最多 2,000 个字符的可选备注。忙碌的提交阶段会冻结正在发送的请求所捕获的列表。

输入框渲染一个“N annotations”标签和一个全部移除控件。指针悬停或键盘聚焦会打开卡片，列出每段文本及其编号、“Selected text”说明、备注编辑器和删除；激活某段文本会滚动到它的来源标记。对话中的来源标记读取同一个列表。

发送时，外壳在模型文本前加上一个 `<response-annotations>` 信封，在显示文本前加上 `@Annotation 1 … @Annotation N` 标签，二者都以一个空格与用户正文相连。因此信封现有的投影会重现显示文本，历史记录仍像以前一样从持久消息推导编号气泡；信封新增可选的 `comment` 字段。允许只发送批注。发送成功时恰好消耗所捕获的批注；失败时保留它们。

持久化草稿把批注以偏移量 `-1` 保存在文本旁边。批注仍为内联引用时保存的草稿，其 `@Annotation N` 标记带有非负偏移量；恢复时会把每个匹配的标记从文本移入列表，并忽略失效条目。

### 波形移动连续且平滑

每个动画帧只读取一次分析器并写入当前步的采样桶。每 97 毫秒一步，采样值取该桶均值的 60% 加峰值的 40%。保留的 RC52 包络每经过一格按 0.86 衰减并保持可见尾迹，再经过非对称平滑（上升 0.6，衰减 0.25）；静音稳定到距底线 0.005 以内时直接回到底线。追赶会补齐经过的格数，工作量上限为 72 个采样，不会按错过的帧数增加分析器读取次数。RC52 的安静语音增益和静音阈值保持不变。72 根竖条位于比视口宽一个竖条间距的轨道上；轨道通过 `--dictation-progress` 每步滑动一个间距，因此竖条连续移动，最新采样从右边缘进入。移动全程仍约七秒。减少动态效果时使用统一且不平滑的电平，不滑动。

仅含附件的发送与文本发送进入同一个输入状态机事务。提交期间拒绝重复 Enter 和附件修改，资源释放会中止请求，同步或异步失败都会保留批注供重试。成功结算会保留捕获草稿之后追加的文本。会话挂载会恢复仅含批注的草稿，即使用户正文为空；旧版迁移只移除完整匹配的标记。删除操作重新编号某条批注时，其打开的备注编辑器会关闭，防止旧备注写入另一段文本。

## Verification

客户端测试覆盖：不写入草稿的批注附件、重新编号、信封中的备注、只发送批注、失败时保留、已发送模型文本投影回显示前缀、附件草稿与旧版内联草稿的恢复、失效附带数据的拒绝，以及输入框标签和卡片的键盘聚焦、导航、编辑、删除和全部移除。波形测试固定了平滑后的起音、步内进度、平缓衰减、节流后的追赶、回到底线、减少动态效果和资源释放。

打包验收仍需要同一个便携 EXE：一到三条批注在滚动、调整窗口、发送和重新加载下的表现，以及至少 15 秒真实语音和静音的录制，并在录制时的显示缩放下测量移动速度。两项都只有产品负责人的视觉验收才能关闭。

## Supersession and related decisions

本决策部分取代 [Giana Code Putri 交互控件](2026-09-02-giana-code-putri-interaction-controls.zh.md)：其中的输入框批注控件和仅按步推进的波形被替换，而来源偏移量、持久投影、导航规则和七秒移动目标仍然有效。

## Alternatives considered

**用标签遮住内联标记。** 未采用，因为这些字符仍在可编辑草稿中，光标可以进入，而单独的气泡行仍然重复显示批注。

**用 CSS 过渡为每根竖条的高度做动画。** 未采用，因为竖条会原地变形而不是移动，每步的跳变仍然存在。

**只把批注保存在模型文本中。** 未采用，因为输入框需要在发送前提供可编号、可编辑、可删除的条目，而历史渲染已经依赖信封到显示文本的投影。

## Consequences

用户正文与批注不再共用缓冲区，因此输入、撤销和复制只作用于用户撰写的文本。除可选备注外，持久线格式不变，因此早期历史照常渲染。波形在录音期间每帧读取分析器而不是每步读取一次，带来少量固定开销。
