# Agent Note: 让本地模型停止期限覆盖宿主清理

[English](2026-09-16-local-model-stop-deadline.md) | 中文

Status: implemented

## Problem

Preview 生命周期使用全局三分钟阶段期限，而临时 systemd 单元本身可能用满三分钟停止模型。排空和端点交接会先消耗生命周期期限的一部分，因此调用方可能在 systemd 完成其拥有的清理前几秒超时。自动路由还会把明确的资源租约拒绝报告为 `NO_CAPACITY`，用错误的 GPU 容量诊断掩盖争用。

## Decision

Giana CoWork Preview 路由采用六分钟的 `stop` 期限和三分半钟的 `verify-stopped` 期限。这些路由级期限覆盖停止前排空、现有 systemd 清理时段和观察余量，但不改变宿主终止策略。明确的目标租约拒绝发生后，自动路由仍继续尝试下一个已准入目标；如果所有候选目标均未成功，则返回 `RESOURCE_TARGET_UNAVAILABLE`。`NO_CAPACITY` 仅用于已完成的预检容量拒绝。

## Alternatives considered

**缩短 systemd 清理时段。** 这会通过减少模型正常退出的机会来掩盖生命周期期限不匹配问题，而且在没有证据证明更短时段安全的情况下改变宿主清理策略。

**把延迟停止视为成功。** manager 在自身期限后无法宣称成功，因为远程变更可能仍未结算。延长负责该操作的阶段可保留失败时关闭语义，并让现有回执记录真实结果。

**继续把租约争用映射为 `NO_CAPACITY`。** 租约所有权和硬件容量需要不同的恢复操作。保留租约错误可避免建议不必要的模型卸载或 GPU 重置。

## Consequences

当现有模型正在排空时，经过批准的切换可能等待更长时间，但生命周期仍受路由期限、现有操作期限和租约期限约束。聚焦测试会区分租约拒绝与测得的容量耗尽。原生资格验证仍必须在精确的便携候选版本上证明停止、停止验证、启动、健康检查、探测、回滚和 DOTS 受保护路径。
