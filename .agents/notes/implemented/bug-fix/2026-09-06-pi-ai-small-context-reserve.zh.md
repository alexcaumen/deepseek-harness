# Agent Note: 为小上下文窗口限制 pi-ai 预留量

Status: implemented

[English](2026-09-06-pi-ai-small-context-reserve.md) | 中文

## 问题

pi-ai 0.82.1 在限制输出前扣除固定的 4,096 token 估算预留量。因此，如实声明为 4,096 token 的本地模型即使提示词为空，也只收到一个输出 token 的额度。修改模型描述来绕过这一预留量，会向提示词准入和用量报告提供错误的容量信息。

## 决策

仓库拥有针对特定版本的 [pnpm 补丁](../../../../patches/@earendil-works__pi-ai@0.82.1.patch)，通过[工作区配置](../../../../pnpm-workspace.yaml)和机械生成的[锁文件](../../../../pnpm-lock.yaml)绑定。补丁仅修改已发布 SDK 限制函数的预留量计算。[适配器 token 策略](../../../../packages/llm/llm-pi-ai/README.zh.md)定义预留量和输出语义；适配器分发和 SDK 的 `buildBaseOptions` 使用同一个已打补丁的函数。不涉及加载器 hook、模型专属例外、虚增模型容量或适配器生产代码变更。

## 考虑过的替代方案

**虚增模型上下文容量。** 不采用，因为这会使准入和报告相信服务器实际上不提供的窗口容量。

**保留私有加载器 hook 或修改已安装依赖文件。** 不采用，因为这些变更不会随仓库依赖图传递，还可能通过共享文件影响其他工作树。

**仅在适配器中限制输出。** 不采用，因为 SDK 可以在分发后再次应用其固定预留量。现有适配器限制逻辑保持不变，并与 SDK 一致。

## 结果与影响

小窗口保留可用的输出空间，而至少 32,768 token 的窗口保持上游预留量。请求上限、模型输出默认值、非正窗口处理和饱和时一个 token 的下限均保持上游行为。饱和不代表提示词能够容纳：分词和提供方开销仍是估算值，过大的输入仍可能被服务器拒绝。

补丁针对已发布的 JavaScript 实现；类型声明仍然有效，上游 source map 不重新生成。精确版本和补丁哈希使依赖升级必须明确决定重新应用或移除补丁。离线且忽略脚本的安装使用 pnpm 的只读存储模式，仅重新链接本工作树的依赖副本。

## 验证

[SDK 预算测试](../../../../packages/llm/llm-pi-ai/tests/context-budget.spec.ts)在预留量下限、整数取整边界、4K/8K 窗口、32K 转折点和更大窗口上执行已安装的限制函数及 `buildBaseOptions`。它们覆盖空和非空提示词、饱和与溢出、模型默认值、调用方上限以及未知窗口行为。[分发测试](../../../../packages/llm/llm-pi-ai/tests/sdk-options.spec.ts)固定模型元数据不变，并断言 SDK 第二次限制前后的精确输出预算。拥挤的 8K 回归用例使用 16,000 个字符，得到 4,000 个估算输入 token 和 3,168 个输出 token。

这些测试无需密钥，模拟提供方流并验证选项路径。它们不验证真实模型、GPU、提供方分词器、完整 profile 渲染器或组装后的应用转录；这些检查不在本次有界补丁任务范围内。
